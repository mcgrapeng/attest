# fixture：defect-mixed-subject

第一人称豁免把**整句**吞掉 —— 一句里混着第三方信息，也被当成第一人称豁免。

**期望判定**

| 判据 | 期望 |
| --- | --- |
| 退出码 | `1` |
| 计划对齐 | 出现「1 条钉不直接引用目标模块」⇒ 钉对目标模块**零覆盖** |
| 零覆盖证据 | 出现「不直接引用目标模块的任何代码」⇒ 说清是"钉钉到别的文件去了" |
| 钉有区分力 | 出现「没有可判的变异点」⇒ 判据**跳过**（not-applicable 档），不是判红 |
| 误报为 0 | **不**出现「机器推导出、计划里没有」⇒ DP 是在计划里的，不该报"漏了" |

**为什么有它**

前面几个 fixture 的红都落在**内容**上（少一条判定点、少一条归属、
钉判不了、钉没判力）。这条落在**对象**上：不变式 I1 写得很好，
但它的「钉」指向 `src/unrelated.test.ts` —— 那个文件跟被测模块**毫无关系**。

一个不引用目标模块的测试文件，**不可能**覆盖目标模块的任何判定点。
工具要能认出这一点，并且给「对目标模块零覆盖」这条具体结论。

同时它覆盖四档里的最后一档 **not-applicable**：钉的文件与被测模块之间
没有任何相对路径可达的源码 ⇒ **没有可判的变异点** ⇒ 这条判据**跳过**，
不是判红、也不是"判不了"。四档各自可区分，是这套工具不塌成一档的前提。

**怎么跑**

```bash
bash fixtures/run_fixtures.sh          # 全部 fixture
```

单独跑这一个：

```bash
cd fixtures/defect-mixed-subject
python3 ../../scripts/readiness.py src --repo . --plan plan.md
```

**已知的环境依赖**

需要 `node`（22+）。判定点推导需要 TypeScript 后端（仓库内或全局 `tsc`）；
没有时推导等级降到 L2（词法层），本 fixture 的 DP 集在 L2/L3 下相同 ⇒ 结论不变。
