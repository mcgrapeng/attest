# fixture：no-tests

**期望判定**

| 判据 | 期望 |
| --- | --- |
| 结论措辞 | 输出里**不**出现「达到交付条件」⇒ 不能因为"没找到红"就说可以交付 |
| 测试全绿这条 | 输出里**不**出现「✓ 测试全绿」、**不**出现「没有失败用例」⇒ 这条判据不得是 ✓ |
| 判据仍在 | 输出里出现「测试全绿」⇒ 这条判据仍然被报告（只是状态不是 ✓） |

**为什么有它**

评审会的第一条，也是**一票否决级**：

> 「你的『测试全绿』在一个测试都没跑的时候是绿的。」

复现出来的形状是：模块 1 个 `.ts` 文件、无任何测试、无任何导出 ⇒
报告里写着「✓ 测试全绿 — 没有失败用例」、结论「达到交付条件」、**退出码 0**。

一个测试都没找到的时候，"没有失败用例"和"测试全绿"是两回事。
这条 fixture 要求工具把这种情况说清楚（"没找到测试文件 ⇒ 判不了"），
而不是拿"没找到红"当"全绿"。

注意这里**不**钉退出码：把这条判据判成 `skipped` 还是 `fail`，
是工具的口径选择，两种都算数；"结论不得说可以交付"才是硬要求。

**怎么跑**

```bash
bash fixtures/run_fixtures.sh
```

单独跑：

```bash
cd fixtures/no-tests
python3 ../../scripts/readiness.py src --repo .
```

**已知的环境依赖**

无。不需要 node（这个模块没有测试可跑）。
