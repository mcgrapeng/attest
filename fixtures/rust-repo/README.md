# fixture：rust-repo

**期望判定**

| 判据 | 期望 |
| --- | --- |
| 退出码 | `2` |
| 报错说明 | 输出里出现「TS/JS/Python」⇒ 说清了当前只实现了哪几种语言 |
| 不给假结论 | 输出里**不**出现「✓」⇒ 不是满屏打勾 |

**为什么有它**

评审会上的原话是：

> 「你的『测试全绿』在一个测试都没跑的时候是绿的。」

这条 fixture 换了个角度问同一个问题：**在工具根本没能力分析这个模块的时候，
它会不会照样给一屏 ✓？**

工具的约定是：识别不出源码文件 ⇒ 退出码 2 + 说清原因，**不给关于"空"的 ✓**。
Rust/Go 命中这条（SKILL.md 第 74-76 行）。一个满屏 ✓ 但其实什么都没测的报告，
比报错更糟。

注意这里**不**要求工具支持 Rust —— 要求的是"认不出来就说认不出来"。
哪天工具支持了 Rust，这条 fixture 的期望要跟着改（退出码不再是 2）。

**怎么跑**

```bash
bash fixtures/run_fixtures.sh
```

单独跑：

```bash
cd fixtures/rust-repo
python3 ../../scripts/readiness.py src --repo .
```

**已知的环境依赖**

无。不需要 node，也不需要 cargo。
