# fixture：ts-colocated

**期望判定**

| 判据 | 期望 |
| --- | --- |
| 退出码 | `0` |
| 测试发现 | 报告里出现「单测 1 个」⇒ 工具认得出 colocated 的测试文件 |
| 导出引用判定 | 出现「导出的逻辑都有测试」，**不**出现「零引用」⇒ 被测到的导出（`add` / `subtract`）不算零引用 |
| 测试车道 | 出现「没有失败用例」⇒ 测试真跑过且真的绿了 |

**为什么有它**

这是**健康仓库**的样子：测试与源码同目录（colocated），导出被测试引用到。
它钉住两件事：

1. 工具的测试发现没把 colocated 的测试漏掉（漏了会误报"导出零引用"）。
2. 「导出的逻辑都有测试」这条判据在**确实有引用**时不误报红。

它是回归套件的**基线** —— 另外四条 fixture 测的是各种"坏形状"，
这条测"好形状没被误伤"。任何一条判据改坏，第一个撞上的是它。

**怎么跑**

```bash
bash fixtures/run_fixtures.sh          # 全部 fixture
```

单独跑这一个：

```bash
cd fixtures/ts-colocated
python3 ../../scripts/readiness.py src --repo .
```

**已知的环境依赖**

需要 `node`（22+，能直接跑 `.ts` —— Node 22.18 起默认开启类型擦除）。
没有 node 时测试车道跑不起来，"测试全绿"会判 skipped 而不是 pass。
